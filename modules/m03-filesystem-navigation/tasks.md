# Filesystem Navigation Tasks

**Objective:** Navigate and build directory structures anywhere on the filesystem without getting lost,
and locate a file you don't already know the exact location of.

> There is no solutions file for this stage. This checklist guides the work — it doesn't contain it. See
> `brief.md` for the full objective, scope, stack constraints, and definition of done, and fill in
> `write-up-template.md` as you go, not after.

## Setup

- [ ] Confirm with your trainer: how deep or complex your structure needs to be, if your design is
      borderline.
- [ ] Decide the organizational scheme for your project structure before you create anything.

## Build

- [ ] Research the "Research:" questions under each Scope bullet in `brief.md` before you start.
- [ ] Explore your own filesystem and note what lives in each top-level FHS directory you find.
- [ ] Move around using both absolute and relative paths, and note when each is the better choice.
- [ ] Create your nested directory structure, at least three levels deep, without stepping into each
      level one at a time.
- [ ] Populate the structure so it reflects your organizational scheme, not a flat dump.
- [ ] Locate at least one file in it using a search tool rather than browsing, and keep the command.

## Verify

- [ ] Confirm the structure is at least three levels deep and was created in one step.
- [ ] Practice stating the absolute path to any file in the structure without running a command.
- [ ] Confirm you found a file with a search tool, not by visual browsing.

## Write-up

- [ ] Under "What I built," describe the structure you designed and how you located a file in it.
- [ ] Under "Why it's built this way," explain your organizational scheme and the depth tradeoff.
- [ ] Under "How to build it," write a guide to building and navigating a nested structure in one step
      and finding a file without browsing.
- [ ] Under "Concepts worth explaining," pick 1–2 ideas (the FHS, or absolute vs. relative paths) and
      explain each in your own words.
- [ ] Under "What tripped me up," capture anything about paths or structure that confused you.
- [ ] Under "Checkpoint evidence," show the structure (e.g. a tree listing) and the search command.
- [ ] Under "What I'd do differently," reflect on what you'd structure differently.
- [ ] Final self-review: re-read your work against M3's definition of done.
