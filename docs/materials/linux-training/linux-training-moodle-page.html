What this program is

This course is architected as a layered stack, mirroring how a real data infrastructure stack is layered on Linux — each layer assumes the layer below it is solid. No prior Linux experience is assumed: Module 0 sets up a verified, working Linux environment (WSL2, a VM, or macOS-in-a-Linux-VM) before Module 1 begins.

This build currently covers OS foundations, filesystem handling, access control & software installation, automation & scheduling, and security & secrets hygiene — culminating in a capstone that integrates all of it into one running pipeline. It does not yet include containers or orchestration (Docker/Kubernetes) or a separate observability module — those stay out of scope until the course grows to cover them.

The capstone is the systems-integration checkpoint

It wires shell scripting (M9), scheduling (M8), and secrets hygiene (M13) into one pipeline — idempotent, scheduled via cron, credentialed through an environment variable, and proven under both a valid and a deliberately malformed input. It does not use Docker, Kubernetes, or a separate observability tool.

Suggested pace

Follow the module order — each layer assumes the one below it is solid, and the modules within a week hand capability to each other (e.g. M8's cron depends on M9's scripting). No fixed hours-per-day figure is set for this build; move at the pace the dependency graph, not a clock, sets.

The one rule

Prove failure, not just success. Every hands-on checkpoint in this course — and the capstone's required validation criterion — asks you to run your work against a deliberately invalid or malformed input, not only the happy path. A script that only works when nothing goes wrong isn't done.
